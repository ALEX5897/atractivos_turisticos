# Implementar Formato de Numeración para Campos de Base de Datos en Quito Turismo

## Descripción
En el módulo de atractivos, el campo de número ('n' en la base de datos, que representa la numeración de orden del listado) debe contar de la siguiente manera: 001, 002, 003, ..., 010, 011, 012, etc. En los catálogos, la numeración debe ir como 01, 02, 03, etc., para la generación de códigos.

## Tarea
- Modificar el esquema de base de datos o la lógica de inserción para asegurar que el campo 'n' en atractivos use formato de 3 dígitos con ceros a la izquierda (001, 002, etc.).
- Para catálogos, usar formato de 2 dígitos con ceros a la izquierda (01, 02, etc.).
- Implementar lógica de generación de códigos que utilice estos formatos numéricos.
- Asegurar que la numeración sea secuencial y automática al insertar nuevos registros.

## Archivos relevantes
- `database/atractivos_turisticos.sql`: Esquema de base de datos
- `backend/src/routes/atractivos.js`: Lógica de API para atractivos
- `backend/src/routes/catalogos.js` y `catalogos-admin.js`: Lógica para catálogos
- Servicios frontend en `frontend/src/services/`: Para llamadas a API

## Pasos sugeridos
1. Revisar el esquema actual de la tabla atractivos y catálogos.
2. Actualizar triggers o lógica de inserción para formatear el campo 'n'.
3. Modificar las rutas de API para generar el siguiente número disponible en el formato correcto.
4. Probar la inserción de nuevos registros para verificar la numeración secuencial.

## Notas
- La numeración debe ser única por tabla/entidad.
- Considerar concurrencia si múltiples inserciones ocurren simultáneamente.
